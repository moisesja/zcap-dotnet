# Issue #36 — Post-#34 W3C-flat path rewrites `proof.created` and drops unmodeled proof fields

GitHub: https://github.com/moisesja/zcap-dotnet/issues/36

## Two distinct bugs (both in [`ProofSigningPayloadBuilder.ToFieldDictionary`](src/ZcapLd.Core/Cryptography/ProofSigningPayloadBuilder.cs))

### Bug 1 — `proof.created` and `capability.expires` get rewritten
The current path round-trips through the typed model. `IsoUtcMicrosecondDateTimeConverter` normalizes any DateTime string to `yyyy-MM-ddTHH:mm:ss.ffffffZ` on Read+Write. Result: an on-wire `"2026-04-29T00:00:00Z"` becomes `"2026-04-29T00:00:00.000000Z"` after re-serialization. The verifier's canonical bytes diverge from what the signer signed, so cross-stack verification fails.

W3C / Data Integrity contract: every other implementation treats the timestamp as opaque and JCS-canonicalizes verbatim. Our converter violates that.

### Bug 2 — unmodeled proof fields (`domain`, `nonce`, `id`, `challenge`) silently dropped
`ToFieldDictionary` serializes through the typed `Proof` model. Anything not declared on `Proof.cs` is lost. The intent we documented in PR #35 ("copy minus `proofValue`") is not honored — we copy *the model's projection* of the proof.

## Architectural choice

The issue lays out two routes:

**Option 1 (minimal type change):** make `Proof.Created` a `string` and `Capability.Expires` a `string?`, add `[JsonExtensionData]` to capture unmodeled fields. **API breaking — bumps to v3.0.0.**

**Option 2 (canonicalize from source JSON):** plumb raw JSON through the verification pipeline, canonicalize from the wire bytes directly. Largest churn; cleanest invariant.

**Option C (recommended — raw JsonElement capture, non-breaking):** keep the typed `DateTime` API. Add a hidden `[JsonIgnore] internal JsonElement? RawJson` capture on `Capability` and `Proof`. Custom `JsonConverter<Capability>` / `JsonConverter<Proof>` populate it during deserialization. `ToFieldDictionary` uses the raw capture verbatim when present (verifier path), falls back to model serialization when absent (signer path). Add `[JsonExtensionData]` for round-tripping unmodeled fields on serialize-fallback. **Ships as v2.0.1 — non-breaking.**

**Decision: Option 1 — full v3.0.0 break.** User accepted the API breakage rather than carry the converter complexity. `Proof.Created` becomes `string`, `Capability.Expires` becomes `string?`, add `[JsonExtensionData]` to round-trip unmodeled fields, delete the converter.

## Review

### What changed
- [src/ZcapLd.Core/Models/Proof.cs](src/ZcapLd.Core/Models/Proof.cs): `Created` is now `string?` (verbatim on-wire value); added `[JsonExtensionData] AdditionalProperties` for unmodeled fields (`domain`, `nonce`, `id`, `challenge`, custom extensions) and a read-only `CreatedAt` accessor for parsed DateTime.
- [src/ZcapLd.Core/Models/Capability.cs](src/ZcapLd.Core/Models/Capability.cs): `Expires` is now `string?`; added `[JsonExtensionData] AdditionalProperties` and a read-only `ExpiresAt` accessor.
- [src/ZcapLd.Core/Models/ZcapTimestamps.cs](src/ZcapLd.Core/Models/ZcapTimestamps.cs): new public helper for formatting / parsing ZCAP-LD timestamp strings. `Format` writes `yyyy-MM-ddTHH:mm:ss.ffffffZ`; `Parse` accepts any ISO-8601 shape and returns UTC.
- Deleted `src/ZcapLd.Core/Cryptography/IsoUtcMicrosecondDateTimeConverter.cs` — no longer needed; the signer formats the string directly, the verifier preserves the wire string.
- [src/ZcapLd.Core/Cryptography/JsonCanonicalizer.cs](src/ZcapLd.Core/Cryptography/JsonCanonicalizer.cs): `Utf8JsonWriter` now uses `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` so the canonicalizer escapes only what RFC 8785 §3.2.2.2 requires (`"`, `\`, control chars). Default encoder was escaping `+`, `<`, `>`, `&` to `\u00xx`, breaking byte equality with peer implementations on timestamps with offsets like `+00:00`.
- [src/ZcapLd.Core/Cryptography/ProofSigningPayloadBuilder.cs](src/ZcapLd.Core/Cryptography/ProofSigningPayloadBuilder.cs): `CloneCapabilityWithoutProof` now preserves `AdditionalProperties` so verifier-path canonicalization sees unmodeled wire fields.
- [src/ZcapLd.Core/Services/SigningService.cs](src/ZcapLd.Core/Services/SigningService.cs): formats `created` via `ZcapTimestamps.Format(DateTime.UtcNow)`.
- [src/ZcapLd.Core/Services/CapabilityService.cs](src/ZcapLd.Core/Services/CapabilityService.cs) and [VerificationService.cs](src/ZcapLd.Core/Services/VerificationService.cs): use `ExpiresAt` for time comparisons; format DateTime callers' input to canonical string when storing on the model.
- [tests/ZcapLd.Core.Tests/Compliance/CrossLanguageJcsInteropTests.cs](tests/ZcapLd.Core.Tests/Compliance/CrossLanguageJcsInteropTests.cs): updated existing known-answer tests to use string timestamps; added Theory pinning verbatim preservation across 5 timestamp shapes (`...Z`, `...000000Z`, `...123Z`, `...123456789Z`, `+00:00`); added tests for unmodeled proof and capability fields surviving the canonicalization round-trip.

### Test results
- 293/293 tests pass (287 pre-existing + 6 new cross-language interop tests).
- New tests would have failed against the v2.0.0 `IsoUtcMicrosecondDateTimeConverter`-based path — they're explicit regression guards for the issue's two reproductions.

### Breaking change
- `Proof.Created`: `DateTime` → `string?`. Read parsed via `Proof.CreatedAt`. Set with `ZcapTimestamps.Format(...)` or any ISO-8601 string.
- `Capability.Expires`: `DateTime?` → `string?`. Read parsed via `Capability.ExpiresAt`. Set similarly.
- These are the only public-API signature changes. All other consumer code paths continue to work — `CapabilityService.DelegateCapabilityAsync(..., DateTime? expires)` still takes a DateTime for caller ergonomics; the service formats it to a string internally.
