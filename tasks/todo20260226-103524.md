# Fix stale assembly in NuGet package

## Plan

- [x] Verify current pack/release workflow behavior and stale-build risk points.
- [x] Update CI/release workflows to enforce clean build inputs before `dotnet pack`.
- [x] Validate locally by packing `ZcapLd.Core` with version `0.2.0` and inspecting assembly version inside `.nupkg`.
- [x] Capture regression-prevention lesson in `tasks/lessons.md`.

## Review

- Root cause confirmed: release/CI workflows used `dotnet pack --no-build`, which can package stale binaries unless a clean rebuild is guaranteed first.
- Updated workflows:
  - `.github/workflows/ci-core.yml`
  - `.github/workflows/ci-aspnet.yml`
  - `.github/workflows/release-core-nuget.yml`
  - `.github/workflows/release-aspnet-nuget.yml`
- Changes applied:
  - Added explicit `Clean` step (`dotnet clean ... --configuration Release`) before build.
  - Added `--no-incremental` to build steps.
  - Kept pack as `--no-build` after deterministic clean build.
- Updated local release guidance:
  - `docs/NUGET-RELEASE.md` now uses `clean -> build --no-incremental -> test --no-build -> pack --no-build`.
- Validation commands:
  - `dotnet clean src/ZcapLd.Core/ZcapLd.Core.csproj --configuration Release`
  - `dotnet build src/ZcapLd.Core/ZcapLd.Core.csproj --configuration Release --no-incremental -p:Version=0.2.0 -p:PackageVersion=0.2.0 -p:AssemblyVersion=0.2.0.0 -p:FileVersion=0.2.0.0`
  - `dotnet pack src/ZcapLd.Core/ZcapLd.Core.csproj --configuration Release --no-build -p:Version=0.2.0 -p:PackageVersion=0.2.0 -p:AssemblyVersion=0.2.0.0 -p:FileVersion=0.2.0.0 -o artifacts/core`
  - `pwsh -NoLogo -NoProfile -Command "[System.Reflection.AssemblyName]::GetAssemblyName('/tmp/ZcapLd.Core.0.2.0.dll').Version.ToString()"`
- Validation result:
  - DLL extracted from `artifacts/core/ZcapLd.Core.0.2.0.nupkg` reports assembly version `0.2.0.0`.
