# Issue #48 — Support delegated zcap `proof` as object or array of proofs

Branch: `48-proof-object-or-array` (based on `47-controller-string-or-array`, not main)

## Problem
ZCAP-LD v0.3: a delegated zcap's `proof` MAY be a single DI proof object **or** an array
of proof objects; at least one MUST be a `capabilityDelegation` proof. Today
`Capability.Proof` is a single `Proof?` and the verifier assumes exactly one proof.

## Design — `ProofSet` value type (mirrors #47 `ControllerSet`)
Shape-preserving immutable wrapper; single object stays an object, array stays an array.

### New files
1. `src/ZcapLd.Core/Models/ProofSet.cs`
   - `IReadOnlyList<Proof> Values`, `Count`, `IsEmpty`, `IsArrayForm`, `Primary` (Values[0]).
   - `FirstDelegationProof()`, `DelegationProofs()`, `FirstDelegationProofWithChain()`.
   - `FromSingle(Proof)`, `FromValues(IEnumerable<Proof>, asArray=true)` (throws empty/null).
   - implicit ops from `Proof` and `Proof[]`; `[JsonConverter(typeof(ProofSetJsonConverter))]`.
2. `src/ZcapLd.Core/Cryptography/ProofSetJsonConverter.cs` (internal)
   - Read: object → FromSingle; array → FromValues(asArray:true); reject empty array /
     non-object entry (JsonException); null → null.
   - Write: array-form → JSON array; else single proof object. Each Proof serialized via
     normal STJ (honours [JsonExtensionData], WhenWritingNull).

### Modified
3. `Capability.Proof`: `Proof?` → `ProofSet?` (keep `[JsonPropertyName("proof")]`,
   `[JsonIgnore(WhenWritingNull)]`). Assignments from a `Proof` keep compiling (implicit).
4. `VerificationService`:
   - Split `VerifyDelegationProofAsync` into a per-proof helper + a loop over
     `Proof.DelegationProofs()`; succeed if ANY delegation proof verifies (sig + parent
     auth + chain). Per-proof helper is try/catch→false so one bad proof doesn't abort.
   - `BuildCapabilityChainAsync` uses `Proof.FirstDelegationProofWithChain()` for the chain.
   - Root `Proof != null` guards unchanged (non-null ProofSet always has ≥1).
5. `CapabilityService`:
   - `BuildCapabilityChain` reads parent's `FirstDelegationProofWithChain()`.
   - `ValidateCapabilityAsync`: delegated MUST have ≥1 `capabilityDelegation` proof.
   - delegation still assigns a single `Proof` (single wire form) — default unchanged.
6. `SignatureVerifier.VerifyCapabilitySignature`: verify the first delegation proof.

### Tests
7. Migrate existing `X.Proof!.<member>` → `X.Proof!.Primary.<member>` (reads + tamper sets).
8. New `Models/ProofSetTests.cs`: object/array round-trip, single-element-array stays array,
   reject empty array / non-object, FirstDelegationProof selection.
9. New `Services/MultiProofVerificationTests.cs`: array with one valid delegation proof
   verifies; none-delegation fails; delegation present but wrong signer fails; delegation
   present but bad/missing chain fails; valid delegation surrounded by other proofs verifies.
10. JCS pin in `CrossLanguageJcsInteropTests`: capability serializes `proof` as array;
    sign-time bytes for the chosen delegation proof == verifier-time bytes.

### Docs
11. CHANGELOG under 3.0.0 (Added ProofSet/converter; Changed Capability.Proof type — breaking API).

## Review (completed)
- Added `ProofSet` (`src/ZcapLd.Core/Models/ProofSet.cs`) + internal `ProofSetJsonConverter`.
  Shape-preserving: single proof → bare object, array → array. Implicit conversion from a
  single `Proof` keeps `capability.Proof = signedProof;` compiling.
- `Capability.Proof`: `Proof?` → `ProofSet?` (breaking API; single-proof wire shape unchanged).
- `VerificationService`: `VerifyDelegationProofAsync` now iterates `DelegationProofs()` and
  succeeds if ANY verifies (per-proof helper is try/catch→false, so one bad proof doesn't
  abort the rest). `BuildCapabilityChainAsync` uses `FirstDelegationProofWithChain()`.
- `CapabilityService`: chain build reads parent's `FirstDelegationProofWithChain()`;
  `ValidateCapabilityAsync` requires ≥1 `capabilityDelegation` proof on delegated zcaps.
- `SignatureVerifier.VerifyCapabilitySignature` verifies any delegation proof (any-verifies, mirroring the service).
- Tests: migrated existing `.Proof!.X` → `.Proof!.Primary.X`; added `ProofSetTests` (10),
  `MultiProofVerificationTests` (5 — incl. invalid-then-valid delegation proof still verifies),
  2 JCS interop pins (array shape byte-equal; single proof stays a bare object).
  **Full suite: 351 passed / 0 failed.** Examples run clean end-to-end.
